## 為什麼先手動

先花三個月做爬蟲、資料庫和圖表，然後才發現自己挑不出好假說 —— 這是這類專案
最常見的死法。階段 0 的真正產出不是報酬率，是**知道你在哪類訊號上真的有邊**。

## 每日流程

**機器做**（每天自動，沒訊號就不吵你）：

1. **掃**：跑一輪來源清單（下方）
2. **殺**：跑 01–04 層，算已知度分數，≥60 直接丟並寫進當日日誌
3. **送**：活下來且滿足三條門檻的，產一張決策卡送到你面前

**你做**（有卡才有事，約 3 分鐘）：

4. **判**：❶ 這是真的異常嗎（憑你懂這個圈子）　❷ 什麼會證明我錯
5. **裁**：到期日機器把卡推回來，你答 ❸ 對 / 錯 —— 這一題不能給機器裁

每月 10 日：機器翻月營收，把到期的卡推回來給你裁決。

> 為什麼只有這三題留給人：見 [auto-flow.md](auto-flow.md)。
> 簡單講 —— 否決是規則，可以自動；肯定與認錯不是，而且校準分數的
> 唯一來源就是你的裁決。

## 半導體 / 科技領域的來源清單

### 可自動化（階段 1 會接的）
| 來源 | 看什麼 | 為什麼領先 |
|---|---|---|
| PTT Tech_Job | 抽單、加班、獎金、離職潮、專案取消 | 台灣科技業最真實的地面情報，員工比分析師早知道 |
| 104 / 1111 職缺 | 某公司某部門 JD 數量與內容變化 | 公司在擴張哪條線，比財報早一到兩季說出口 |
| 公開資訊觀測站 | 月營收（每月 10 日）、重訊 | 全球罕見的高頻硬數據，你的 ground truth |
| 法說會逐字稿 | 管理層有沒有提過某個主題 | 用來判斷「市場已經知道了嗎」 |
| Reddit r/hardware 等 | 國際端的產品與需求討論 | 對照台灣端訊號是否同步 |

### 只能人工偵察（不進自動化管線）
| 來源 | 說明 |
|---|---|
| FB 社團 | 產業社團、公司社團情報密度高，但**沒有公開 API**，只能自己看 |
| IG | 同樣封閉，且對 B2B 半導體幾乎沒訊號 |
| Threads | 台灣使用率高，可人工翻；官方 API 不支援全站搜尋 |
| 真人 | 同學、前同事、竹科朋友。**唯一沒人能複製、也沒有 API 的資料源** |

> 人工來源不是次等來源。Camillo 最賺的幾筆都來自親眼所見。
> 差別只在於它進不了自動化管線，所以要靠假說卡的「人工觀察」欄位手動接進來。
