# 自動巡邏流程 · 誰做什麼

建立：2026-08-28
取代：原本「人開卡 → 手動跑五層」的做法。

---

## 為什麼改

8/27 與 8/28 兩天的巡邏日誌，**每一個候選都死在第 04 層（已知度過高）**。
也就是說手動填在 01–03 的欄位全部是白工 —— 那些公司的消息早就在法說會和
財經媒體上了，而這件事機器查一次就知道。

**原則：讓機器做否決，人只做肯定。** 第 03、04 層本來就是否決層
（見 PLAN.md §4），否決是規則判斷，不需要人。

---

## 分工

| 層 | 誰做 | 產出 |
|---|---|---|
| 01 採集 | 機器 | 原始異常清單 |
| 02 語意 | 機器 | 過濾雜訊、合併同一件事、標訊號類型 |
| 03 映射 | 機器出草稿 | 標的 + 曝險 % + **財報原文段落**（沒段落就標「未驗證」） |
| 04 濾網 | 機器 | 已知度分數（下方公式），≥60 直接丟 |
| — | **你** | **決策點 A：兩題** |
| 05 紀律 | 機器 | 建卡、設到期日、到期提醒 |
| — | **你** | **決策點 B：到期裁決 對/錯** |

你只碰兩個決策點。其他都不該進到你眼前。

## 已知度分數（機械公式，不需判斷）

滿分 100，逐項相加：

| 條件 | 分數 |
|---|---|
| 最近一次法說會或財報管理層講過這件事 | +40 |
| 主流財經媒體（工商、經濟、鉅亨、MoneyDJ、UDN）報導 3 篇以上 | +30 |
| 同上，1–2 篇 | +15 |
| 同上，0 篇 | +0 |
| 券商覆蓋度「高」或「極高」（見 watchlist.md） | +20 |
| 近一個月漲幅 > 20%，或曾列處置股 | +20 |

| 分數 | 動作 |
|---|---|
| ≥ 60 | **機器直接丟**，寫進當日日誌的死因表，不進你的收件匣 |
| 30–59 | 進收件匣，標黃：窗口只開一半 |
| < 30 | 進收件匣，標綠：這才是你要看的東西 |

> 用這個公式回頭跑 8/27–8/28 的候選：洋基、雍智、亞翔、帆宣全都是
> 法說會(+40) + 媒體 3 篇以上(+30) + 覆蓋度高(+20) = **90 分**，
> 機器一秒就丟掉了，你一個字都不用寫。

## 送到你面前的門檻

已知度過關**還要再滿足** watchlist.md 的三條，才准佔用你的注意力：

- ✅ 兩個以上獨立來源指向同一件事
- ✅ 跟三個月前的基線比對過，確認是異常不是常態
- ✅ 那家公司券商覆蓋度不高

三條沒到齊，機器一樣只寫進日誌，不送。

### ⚠️ 爬蟲不能跑在 Claude 的雲端 session 裡

2026-08-28 實測：這個環境的出口代理對 **104、1111、Dcard、Google Trends、
證交所 OpenAPI 全部回 403**，跟 PTT 是同一個原因。所以抓取全部放在
**GitHub Actions**（`.github/workflows/daily-patrol.yml`）跑 —— 網路是通的、
有 cron、而且不需要你的電腦開著。

分工變成：

| 誰 | 時間 | 做什麼 |
|---|---|---|
| GitHub Actions | 每天 20:00 | 抓 104 → `data/jobs/YYYY-MM-DD.json` → 偵測異常 → `data/anomalies/YYYY-MM-DD.md` → commit |
| Claude 巡邏任務 | 每天 20:30 | 讀當天的異常報告 → 跑 03 映射、04 已知度（WebSearch）→ 寫日誌 → 有卡才通知你 |

## 怎麼手動跑

```bash
python3 scripts/fetch_104.py     # 抓今天的職缺數
python3 scripts/detect.py        # 跟基線比對，產出異常報告
```

`scripts/watchlist.json` 是名單的機器可讀版，跟 `stage0/watchlist.md` 要一起改。

**基線要養 7 天。** `detect.py` 在歷史不足 7 天前一律不報異常 —— 沒有比較基準
就報異常等於把常態當訊號。所以前一週不會有任何卡，那是正常的。

### 職缺數的兩個限制（要知道，不然會誤判）

1. **關鍵字搜尋不精準**：現在用公司名當關鍵字，會撈到人力仲介代 po 的職缺。
   看**趨勢**（今天 vs 基線）是有效的，看**絕對數字**不準。
   要修就把 `watchlist.json` 的 `company_id` 填上 104 的公司代碼。
2. **抓取失敗 ≠ 開缺數 0**：報告會把兩者分開列。這是 8/27 日誌那個教訓的延伸——
   「沒查成」絕對不能記成「查過了、乾淨」。

> ⚠️ 用網路搜尋做「地面異常」快篩有先天上限：搜尋引擎偏好索引已發布的
> 正式新聞，那些依定義已知度就高。**真正的地面情報只會從職缺數、論壇原文、
> 和真人來。** 這是接 104 職缺優先於一切的理由。
